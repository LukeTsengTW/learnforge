## Request and scope

Human 的需求：新增手寫畫布放大的功能。原本的畫布是固定大小，一題有三小題時寫不下，要解決這個問題；最後把修改交由 sub-agent reviewer 審查，並用 Playwright 進行網頁端的實際測試。

Human 決定（從三個選項中選擇）：**全螢幕＋縮放**，只改 frontend。沒有採用的選項：加大邏輯畫布（以及兩者都做）。理由見下一節。

## Investigation

- 每題的畫布有固定的邏輯大小（`drawing` 設定的 width／height，例如習題題庫為 1200 × 900），筆跡以邏輯座標保存；CSS 只調整顯示寬度。原本畫布的顯示寬度跟著題目卡片：本機 fixture 量到 1440 與 1180 寬的視窗中 814 px、820 寬 692 px、360 寬 280 px。手機上 280 px 寬的畫布要寫三個小題的推導，字必須寫得非常小。
- 加大邏輯畫布會碰到兩個上限：資料庫的 `private.v4_drawing_config_valid` 只接受寬高 100..1200，server 端點陣化的 `DRAWING_LIMITS.maxDimension` 也是 1200。要加大就需要 migration、Edge 部署與付費的 provider canary（確認更大的影像仍能評分），因此 human 選擇只改顯示。
- 座標換算 `(clientX - rect.left) * logicalWidth / rect.width` 本來就以畫布在螢幕上的 rect 為準，所以只要畫布在螢幕上變大，同一套換算就把較大的筆跡對應回相同的邏輯座標；保存的格式、評分與 AI 評分的影像都不需要改。

## Design

- `DrawingCanvas.tsx`：
  - 工具列最後新增一組「放大書寫」：切換按鈕（`aria-pressed`，放大時文字為「結束放大」）；放大時再顯示 1×、1.5×、2×（名稱「縮放 n 倍」），倍率大於 1 時顯示「移動畫面」。放在工具列最後，讓既有的工具順序不變。
  - 放大時編輯區加上 `is-expanded`，成為鋪滿視窗的 modal：`role="dialog"`、`aria-modal="true"`、名稱「放大書寫」；頁面其他部分（編輯區每一層祖先的兄弟元素，直到 `body`）設為 `inert`，原本就是 `inert` 的不動，關閉時只還原自己設定的。放大期間頁面才加入的內容（例如同步失敗的通知與它的連結）不是 `inert`；`focusin` 到編輯區以外時，焦點移回「結束放大」。頁面捲動以模組層級的計數鎖定（第一個鎖定時保存 `documentElement` 的 overflow，最後一個解除時還原）。Esc 透過 `useEffectEvent` 呼叫與「結束放大」相同的 `collapse()`。
  - 放大時編輯區離開頁面的版面，頁面變短，捲動位置可能被瀏覽器夾住（例如在最後一題）。放大時記下頁面的捲動位置，結束放大、編輯區回到頁面之後（`useLayoutEffect`）以 `window.scrollTo` 還原；卸載時不捲動。
  - 畫布外包一層 `.canvas-viewport`。1× 的顯示寬度是 `floor(min(viewport 外寬 − 2, (viewport 外高 − 2) × width / height))`（2 是外框左右各 1 px），寬高取 viewport `getBoundingClientRect()` 的整數部分：border box 包含捲軸，2× 時出現傳統捲軸也不會改變 1× 的大小，避免量測與版面互相觸發；取整數部分讓小數高度的 viewport 在 1× 時不會因不到 1 px 的溢出而出現捲軸。量測在 `useLayoutEffect` 中進行，並以觀察 border box 的 `ResizeObserver`（沒有時用 window `resize`）跟著視窗大小更新。1.5×、2× 是當時量測的 1× 寬度乘上倍率；每個倍率都重新量測 viewport：倍率改變時 viewport 上下的內容可能改變高度，所以由高度決定大小時，2× 不一定正好是 1× 的兩倍（本機 1180 × 820：border box 高 643.219 → 647.609，1× 854、2× 1720）。切換倍率時保持畫面中心的位置。
  - 「移動畫面」：任何指標（滑鼠、手指、觸控筆）拖曳時捲動 viewport，不建立筆畫；`pointercancel` 與失去 pointer capture 時結束。回到 1× 時自動關閉。
  - 筆畫進行中按「放大書寫」、Esc、「結束放大」或切換倍率時，先以既有的 `flushPendingStroke()` 保存已畫的部分，之後的取樣不屬於任何筆畫，筆畫不會因畫布改變大小而跳動。結束放大時倍率回到 1×。
  - 狀態行（既有的 live region）：「已放大書寫。按 Esc 或「結束放大」返回。」、「書寫縮放 n×。」、「已結束放大書寫。」。
- `global.css`：放大時編輯區 `position: fixed; inset: 0; z-index: 30`，以 flex 欄排列工具列、可捲動的 viewport（`overflow: auto; overscroll-behavior: contain`）與下方的按鈕；隱藏畫布下方的說明文字與 Apple Pencil 提醒以留給畫布；「移動畫面」時游標為 `grab`。畫布的 `touch-action: none` 不變。

## Review

Review 由本 session 內的 sub-agent（code reviewer）執行。

- Cycle 1：一項 blocking——1× 的大小以 `clientWidth`／`clientHeight` 量測，不含捲軸；2× 出現傳統捲軸時量測值改變，可能與版面互相觸發。兩項 should-fix。S1（modal 行為）：焦點可以離開放大的編輯區；兩個編輯區同時放大時頁面捲動的還原順序錯誤；一次 Esc 關閉全部；提交進度卡片（z-index 20）會被放大的編輯區（z-index 30）蓋住。修正為頁面其他部分 `inert`（因此不能再放大第二個編輯區，也不能在放大時開始提交）、dialog 語意與捲動的計數鎖定。S2：Esc 或切換縮放時進行中的筆畫因畫布改變大小而跳動，改為先保存。Nit：量測改在 `useLayoutEffect`、結束放大時倍率回到 1×，已修正；「觸控筆優先」時手指不拖曳畫面，刻意保留並列入已知限制。
- Cycle 2：APPROVE。另提一項 should-fix（筆畫進行中按「放大書寫」，例如焦點仍在按鈕上時按空白鍵）與四個 nit：放大後才加入頁面的內容不是 `inert`、結束放大後頁面的捲動位置可能被夾住、小數高度的 viewport 在 1× 時可能出現捲軸、`ResizeObserver` 觀察的 box 與量測的 box 不同。全部修正。捲動位置原本依 reviewer 的建議用 `scrollIntoView({ block: 'nearest' })`，但 browser 證據顯示一般情況（第一題）也會移動頁面，改為還原放大前的捲動位置。修正後重跑全部 gates 與 browser。
- Cycle 3：確認五項修正都正確，沒有 regression 或新發現，APPROVE。
- Release-prep review（同一個 sub-agent）：PASS，沒有 blocking。兩項文件的 should-fix 已修正：2× 的寬度不是 1× 的兩倍時，文件的推導對不上（改為記錄 2× 時重新量測的 viewport 高度）；登入後 smoke 的替代引用 v1.12.0 為先例，但 v1.12.0 有部署前的登入 canary，本版沒有任何登入後的執行（改為明說差異，以 v1.10.2 為較接近的先例）。Nit：cycle 1 的摘要、checklist 的勾選時機、記錄 commit 前的 release tools 結果，已修正。Reviewer 核定登入後 smoke 的替代可以接受。

## Known limitations

- 放大只改變顯示大小；邏輯畫布的大小（資料庫限制寬高 100..1200）不變，所以放大讓字可以寫得較大、較細，不是增加畫布的空間。
- 沒有雙指縮放；倍率只有 1×、1.5×、2×。
- 「觸控筆優先」時手指不會拖曳畫面（為了忽略手掌）；要用「移動畫面」或 viewport 的捲軸。「標準」模式下手指在畫布上是書寫。
- 放大時看不到題目的文字，要結束放大才能再看題目。
- 放大期間才加入頁面的元素不會設為 `inert`。編輯區鋪滿視窗蓋住它們，焦點到達時會移回「結束放大」；不支援 `aria-modal` 的螢幕閱讀器在瀏覽模式下仍可能讀到它們。
- 部署上的 Student Preview（360 寬）結束放大後，頁面回到按下時的捲動位置，但頁面高 8520 → 8508、畫布由 y 457 移到 440。原因沒有確定：編輯區內畫布上方的內容在放大前後沒有差異（唯一留下的差異是畫布下方的狀態行），推測是頁面當時仍在調整版面（例如字型），與 1440 寬在按下前出現的捲動變化相同。
- Browser 證據是桌面的 Chromium（headless shell，傳統捲軸以 headed Chromium）；沒有 iPad、iPhone 或 Android 實機的觸控與觸控筆驗證。
- 登入後的練習頁在部署上沒有驗證（見「登入後 smoke 的替代」）。
