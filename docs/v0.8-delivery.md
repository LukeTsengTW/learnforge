## 2. Architecture

`AuthoringDocument` 保留 raw `source`、檔名、原題庫 id、dirty、version 與 parseState。題庫解析只用既有 `parseQuiz()`；revision、metadata、警告、匯入／匯出及 local draft 由不依賴 server 的函式處理。編寫 route 無須登入；直接開啟它時不初始化 Supabase client。

## 3. Editor

使用標示清楚的 monospace `textarea`，關閉拼字檢查。Tab 插入兩個空格，提供行／欄及 UTF-8 bytes 狀態、內部捲動與行錯誤跳轉。source 上限 1 MiB，沒有新增 IDE/editor dependency。

## 4. Parser reuse

編輯後 300 ms debounced parse；version guard 避免舊結果覆蓋新 source。成功產生正式 `Quiz`；失敗保留文字並顯示 `QuizParseError` 的行、題目 id 與訊息。Parser 仍 fail-fast，每次顯示第一個阻塞問題，沒有另造 DSL parser。

## 5. Preview

Student Preview 使用正式 `QuestionCard`／`QuestionInput`、`Markdown`／KaTeX 與 `DrawingCanvas`；Answer Preview 使用正式 `ResultQuestion` 顯示 canonical answer、solution、rubric。六種題型可操作，作答只在 React memory；「重設預覽作答」只清除該 state。

## 6. Validation

`Valid`／阻塞問題與非阻塞提醒清楚分開。提醒涵蓋重複可見選項、過長標題／題目、缺少 hint 及可疑預估時間，不宣稱能判斷學術內容正確性。

## 7. Metadata inspector

成功解析後從 canonical `Quiz` 與正式 `gradeQuiz()` 計算 id、title、description、subject、tags、revision、estimatedMinutes、current、題數、題型分布、宣告分數、自動評分最高分與手動分數。

## 8. Question navigator

題目按鈕列出 `Qn · type · id`，鍵盤可操作；點選捲動到正式預覽中的該題。

## 9. Templates and snippets

「建立空白題庫」產生可立即通過正式 parser 的一題範例。六種題型範本直接插入 DSL text，使用下一個未占用的 `qN`；計算與畫圖範本預設含兩項 scored rubric。既有 question id 不會改名，unscored rubric 仍合法。

## 10. Import

File API 讀取單一 `.quiz.md`、`.md` 或 `.txt`；UTF-8 使用 fatal decode，超過 1 MiB 或其他副檔名會拒絕。檔案不經過 server。未匯出修改在匯入前須確認。

## 11. Export

下載使用 `Blob`／`URL.createObjectURL`；只清理檔名至安全字元並以 `.quiz.md` 結尾，內容保留編輯器原文，包括原換行。Clipboard API 失敗時嘗試選取 textarea 的 fallback，並顯示結果。

## 12. Local draft

只在按鈕操作時保存一份 `learnforge:author:draft:v1` localStorage 草稿；載入時再次檢查 1 MiB 上限，可清除。與 practice cache／AI cache namespace 分開，不自動同步。

## 13. Revision workflow

已解析 source 才能建立新 revision；作者手動輸入不同的 revision，不推測 `v1-7d7c900e` 的 hash 算法。操作僅複製並局部修改編輯器的 `@quiz` metadata；舊 bundled source 原文保留。UI 明示已發布 revision 不應原地修改，以及舊 current 改 false、新 current 設 true 的檢查清單。

## 14. Catalog simulation

`validateProposedRevisionChange()` 以既有 bundled revision metadata 與新 source 純函式模擬：檢查 quiz id 不變、新 revision 不重複、既有 catalog identity 與 current 合法，並模擬舊 current=false、新 current=true 後恰有一個 current。不修改任何 repository 檔案。現有目錄慣例為 `<quiz-id>/v1.quiz.md`，下個路徑建議如 `src/content/quizzes/demo/v2.quiz.md`。

## 15. AI capability warnings

計算題與畫圖題沿用正式 AI 控制元件的 `hasScoredRubric()` 純函式。具 scored rubric 顯示參考評分／圖像分析可用；缺少時顯示「可正常作答，但不支援」警告。客觀題不受影響；此處不呼叫 AI。

## 16. Security

匯入內容與 raw DSL 只當文字；正式 Markdown renderer 保持 `skipHtml`，KaTeX 保持 `trust: false`。Browser 測試加入 `<script>`、帶 `onerror` 的 `<img>`，預覽沒有產生相應 DOM 節點或執行腳本。損壞的 KaTeX 未使頁面崩潰。

## 17. No server write boundary

編寫 route 不接 AttemptProvider、PracticeRepository 或 Tutor service；預覽答案不寫 local practice cache、不建立 Supabase attempt、不扣 credits。直接進入 `#/author` 時不初始化 Supabase client。瀏覽器流程記錄只有 13 筆靜態資源請求，沒有非靜態網路請求；沒有 Supabase write 或 AI call。

## 18. Tests

新增 26 個測試：raw template、dirty／stale parse、六種範本、metadata／AI capability、local draft、UTF-8／大小／副檔名、匯出 round trip、檔名安全、copy fallback、revision 與 catalog 模擬、六題型正式預覽、Canvas、HTML 安全、覆蓋確認及公開 route。原 267 個測試保留。

## 19. Browser verification

對 production build 實際執行 `#/author` → New → valid preview → 插入 single／calculation → 修改 rubric → Valid → Answer Preview → 插入 drawing 並用 Canvas 作答 → 匯出。接著匯入現有 demo → 改成 `:::broken` 看到 q1／第 22 行 parser error → 修復後恢復預覽。再載入 bundled demo → 原 revision 被拒 → 建立 `v2` → catalog 模擬通過 → 下載 `v2.quiz.md`。Console errors：0。

## 20. RWD and accessibility

實測 360、768、1440 px：前兩者上下堆疊，1440 px 編輯器與預覽左右並排；三者 `document.scrollWidth === clientWidth`，無頁面水平溢位。Editor 有 label、validation 有文字與 aria-live、模式與導覽均為 button、匯入有 label／input、錯誤可點選跳行。

## 27. Known limitations

Parser 為 fail-fast；提醒只指出可檢查處，不驗證答案正確性。編輯器沒有 syntax highlighting，mobile 採堆疊版。localStorage 只有一份手動保存的草稿；清除瀏覽器資料會失去它。Browser 只建議檔名／路徑，作者仍須人工審閱、將新檔放入 Git、更新舊 current、執行題庫與 AI context 檢查並發布。沒有 CMS、伺服器題庫寫入或協同編輯。
