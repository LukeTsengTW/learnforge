## 2. Quiz Catalog 架構

`quiz-loader.ts` 以 typed `import.meta.glob` 在 build 時載入 `src/content/quizzes/**/*.quiz.md`。`createQuizCatalog()` 對每個 quiz id 建立 revision map，另外維護唯一 current revision。Library 只列 current；Result 和舊草稿用 `getQuizRevision(id, revision)` 精確讀取。Catalog 預先計算題數及 deterministic max score，UI 不處理原始 Markdown，也不查資料庫取得題目。Parser error 保留檔名與行號供開發定位；無效檔不使其他有效題庫白畫面。重複 id+revision、多個 current 或缺少 current 會明確失敗。

## 3. DSL metadata 與題目標籤

沿用現有 `@quiz key="value"` 與 `:::question key="value"` 語法。Bundled catalog 要求 id、標題、非空描述、subject、tags、revision、正整數 estimatedMinutes 與明確 current。`tags` 以逗號分隔，trim、小寫化、去重，question tags 可省略且不影響評分。舊 `@quiz id="demo"` 仍可由一般 parser 讀取，維持 v0.1/v0.2 相容。

## 4. Revision 策略

每次修改題目或正解應新增 revision 並保留舊 `.quiz.md`。歷史紀錄以 attempt 的 `quiz_id + quiz_revision` 解析；當 current 不同時顯示舊版提示，再次練習使用 current。舊草稿仍用原 revision，使用者可確認後僅刪該草稿，改用新版。若檔案缺失，History/Result 仍顯示 quiz id、revision、時間及分數快取；不推測答案或錯題。

## 6. 多次作答資料模型與 migration

一個 user + quiz 可有不限數量 submitted attempts，最多一份 draft。第一份 v0.3 migration 在確認遠端實際約束名 `attempts_user_id_quiz_id_key` 後移除全域唯一約束，加入 `(user_id,quiz_id) WHERE status='draft'` 部分唯一索引，以及 `(user_id, submitted_at DESC, id DESC) WHERE status='submitted'` 歷史索引。既有 rows、answers、UUID、Auth users 原地保留；沒有 reset、truncate、repair 或資料重寫。遠端非測試資料仍有原先的一份 draft。

## 7. RLS、trigger 與 RPC

attempts 只允許本人讀取、建立與修改 draft，DELETE 僅 draft；submitted 的 UPDATE 由 `private.lock_submission` trigger 拒絕，答案 UPDATE/DELETE 也受既有 parent lock trigger 拒絕。第二份 v0.3 migration 修正提交後 parent row 的 UPDATE-policy 可見性，使答案 trigger 的 `SELECT ... FOR UPDATE` 能鎖住 submitted parent；實際 mutation 仍被 trigger 阻止。這是 SQL 測試發現並修正的問題。

`get_or_create_quiz_draft` 是 security invoker，以 transaction advisory lock 加部分唯一索引處理同時開始；已有 draft 就回原 UUID。`save_quiz_attempt_v3` 依 UUID、owner、quiz id/revision、startedAt、server `updated_at` CAS 原子寫入 attempt 與 answers。兩個新 RPC 均使用固定空 search path，撤銷 PUBLIC/anon EXECUTE，明確授權 authenticated。v0.2 的 quiz-unique save RPC 已撤銷 authenticated EXECUTE。分數與 grade JSON 只是 client cache，讀取時以 canonical revision 重新評分。

## 8. Repository、草稿生命週期與再次練習

`SupabasePracticeRepository` 統一提供 batch `listCurrentDrafts`、UUID 精確載入、atomic get/create、CAS save、draft-only delete、每頁 20 筆歷史與舊 route 的最新提交 lookup。`QuizAttempt` 原 domain contract 未塞入資料庫欄位；`PracticeRecord` 保存 UUID 與 server version。Library 一次查所有 draft，不做每 card 查詢。

答案先寫帳號及 UUID 隔離的本機 cache，約 800ms 批次同步。重新整理可從同一 UUID 的本機／雲端草稿恢復；不同 UUID 不能互覆。提交鎖定該 UUID。Result 的「再次練習」進入 quiz route，由 RPC 建立或繼續另一份草稿，不改原 submission。重新開始只在確認後刪目前 draft，已提交歷史不刪。

## 9. History、Mistakes、routes

`#/library` 可公開瀏覽；`#/quiz/:quizId`、`#/result/:attemptId`、`#/history`、`#/mistakes` 受 Auth guard 保護。未登入的開始練習會保存登入後目的地。舊 `#/result/:quizId` 導向該題庫最新已提交 UUID；無提交時顯示明確空狀態。HashRouter 保留，適合 GitHub Pages 的 hash route refresh。

History 依 `submitted_at DESC, id DESC` 排序，以 20+1 筆判斷「載入更多」；標題／科目由 bundled catalog 查，不做每筆 DB metadata join。Result 只載入指定 UUID 與其 answers。Mistakes 由已載入的 submitted attempts、answers、exact revision 與 deterministic grader 推導每次答錯的客觀題；未作答、計算、畫圖不算錯題。每筆顯示原答案、正確答案、解答、日期，以及特定 Result/當前 Quiz 連結。沒有 `mistakes` table。

## 10. 本機 v2→v3 遷移

v3 key 為 `learnforge:attempt:v3:<user-id>:<attempt-id>`，另有同帳號 quiz draft index。既有 v2 key 只在 remote attempt UUID 相符且資料通過 decoder 時複製；重試不會重複破壞或刪除 v2。格式損壞時保留原 bytes 的 recovery backup。本機已提交但遠端仍是同 UUID 草稿時，保留本機版本並顯示待同步狀態，雲端確認後才開啟結果。提交後 cache 不可被新作答覆寫，草稿衝突依同 UUID 及 CAS 解決。v0.1 未綁帳號進度仍需使用者明確選擇匯入，原 key 保留。

## 13. 已知限制與 v0.4 建議

- 題目答案隨靜態 bundle 發布，client 分數不能用作防作弊考試成績；計算和畫圖維持人工對照。
- 舊 revision 檔必須保留，否則相關歷史不能安全重算或展示解答。
- Mistakes 只涵蓋目前已載入的歷史頁，較早紀錄需按「載入更多」。沒有單題模式、mastery 計算或 server-side 全歷史聚合。
- 離線可續寫目前已載入的草稿 cache；建立草稿與提交需要雲端。沒有 Realtime 或逐題多裝置合併；recovery 備份沒有 UI。localStorage 容量、共用裝置與無密碼重設限制仍在。
- v0.4 優先：可驗證的帳號復原與 leaked-password protection、recovery UI、多裝置衝突 UX，以及在歷史增長後評估 server-side 錯題摘要。另可評估 pre-existing advisor WARN 的 event-trigger EXECUTE grant。
