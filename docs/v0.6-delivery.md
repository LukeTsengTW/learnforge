## 2. Grading architecture

Result 頁只對可用題目顯示主動操作。Browser 對 `ai-grade` 只送 `requestId`、`feature`、`attemptId`、`questionId`。Edge 驗證登入身分、attempt ownership 和已提交狀態；以 attempt 的 `quiz_id + quiz_revision + question_id` 查 server manifest，再以 RLS user client 取得已保存的答案。Privileged RPC 管理私有 ledger 的查找、保留、完成及退還。Browser 不能指定題目內容、rubric、模型、分數或 credit 成本。

## 3. Supported questions

只支援已提交、答案非空白、已包含在 server manifest 的 `calculation` 題。現有 bundled 題庫中，demo v1 的 q6 符合條件。客觀題與畫圖題不進入此功能；畫圖資料不送 OpenAI。未提交 attempt、不屬於使用者的 attempt、不存在的題目與過長答案均在 provider 呼叫前拒絕。

## 4. Rubric requirements

必須有 1–20 個量化項目，每項描述非空、分數有限且大於 0；項目 ID 由 manifest 生成為 `r1`、`r2` 等，總和須等於題目分數。題庫生成器先檢查，Edge 再檢查；只有文字、缺少分數或分數總和不符的 rubric 不會開放評分。學生答案上限 8192 UTF-8 bytes。

## 5. Model configuration

Tutor 與 grading 共用固定模型 `gpt-6-luna`。評分使用 OpenAI Responses API 的嚴格 JSON schema、`store=false`，不啟用工具，也不接受 browser 指定模型。

## 6. Reasoning effort

Tutor 保持 `low`；計算題評分固定 `medium`。Migration 的 check constraint 與 reserve RPC 同時限制 feature 和 effort 的配對。

## 7. Structured grading schema

成功回覆含 `overallScore`、`maxScore`、逐項 `criterionId / awardedScore / maxScore / status / feedback`、`summary`、`strengths`、`improvements`、`confidence`、`requiresManualReview`。`status` 限 `full / partial / none`；安全拒答轉成固定的無分數 `refusal` 回覆。UI 對應呈現逐項文字狀態，不靠顏色辨識。

## 8. Server score validation

Edge 驗證欄位集合、有限數值、項目數量與唯一 ID；每項 `maxScore` 必須和 canonical rubric 嚴格相等，得分必須在 0 與上限之間，`full / partial / none` 要與得分一致，`overallScore` 要等於逐項加總且不超過題目分數。非法、截斷、格式錯誤或超長的 provider 回覆不會存成有效評分，reservation 會退還或由 TTL 釋放。恢復時再依原題目版本驗證已保存回覆。

## 9. Prompt injection boundary

Canonical 題目、標準答案、解法與 rubric 由 server 準備；學生答案放在獨立標記的 untrusted data 欄位。Instructions 明確要求忽略答案內對角色、評分規準、分數或輸出格式的指令，並容許等價解法與有根據的部分得分。答案不寫入 AI ledger 的 raw prompt 欄位。

## 10. Advisory score semantics

Result 的 AI 建議分數獨立顯示。`attempts`、`answers`、客觀題 deterministic score 及 History 的正式顯示分數不因 AI 評分改變；實測本次提交的自動分數在兩次 AI 評分前後仍為 **0/10**。評分卡只顯示一次「AI 參考評分僅供學習使用，請以教師或題目正式評分規準為準。」

## 11. Quota

沿用每人 5 小時滾動 20 credits。`calculation_grading` 固定 2 credits，由 DB RPC 推導，與 Tutor 的 1／1／2 成本共用 per-user transaction advisory lock。完成消耗額度；provider／schema 失敗退款；已完成的安全拒答消耗 provider 用量並按完成記帳。Client 顯示 DB 回傳的 feature cost，但無法指定成本。

## 12. Persistence / restore

私有 `ai_requests` 保存已完成結果。`ai-responses` 先確認 attempt ownership，再讀本人已完成的最新評分，並按當時的題目 revision 重新驗證。Result reload、從 History 重開只讀取，不呼叫 OpenAI，不再次扣點；已存在回覆在額度不足時仍可讀。

## 13. Regenerate / idempotency

同一 `requestId` 的已完成要求只回放保存結果；reserved 回處理中，失敗／逾時的首次重試維持原 ID。使用者明確按「重新評分」才產生新 UUID、進行新評分並扣 2 credits。恢復 API 選最新完成的評分。

## 15. RLS / RPC

`ai_requests` 保持 RLS 且沒有 browser role 的直接 SELECT／mutation policy；quota／ledger RPC 仍只授權 `service_role`。Edge 的 `withSupabase({ auth: 'user' })` 驗證 JWT，user-scoped RLS client 查 attempt 和 answer，service-role client 只呼叫私有帳本 RPC。不存在與非本人 attempt 使用同類 generic 404。SQL 安全測試涵蓋 RPC 禁權與跨帳號隔離。

- AI 評分是建議，可能誤判；這次 live 測試驗證整合，沒有作為模型準確率 benchmark。ambiguous／unexpected method 可能需人工覆核，正式成績仍以題目／教師規準為準。

- 只有本機 Chromium viewport 驗證，未涵蓋實體裝置、跨瀏覽器與大型 ledger 壓力測試。UI Usage 頁在同一專用帳號的額外點擊因瀏覽器 session 結束而未補做。
