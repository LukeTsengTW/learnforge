# LearnForge v1.2 grading design

This document describes the implementation prepared for v1.2 review. It does not declare v1.2 released; the production version remains v1.1.1 until the separate release rollout.

## Product position

LearnForge is a self-practice platform. It does not provide teacher grading, manual review, approval, instructor override, teacher accounts, or a waiting-for-review state.

Single choice, multiple choice, true/false, and fill questions contribute deterministic or trusted semantic-fill grades to the current practice result. Calculation and drawing questions also contribute to the result in `ai-grading-v3`, with rubric-based partial credit. A blank fill answer or blank calculation answer is unanswered with zero points and does not call an AI provider. A meaningfully blank drawing is unanswered; invalid or oversized drawings and raster failures are submission errors.

The result UI explains: **AI 自動評分僅供學習參考，可能存在誤判。** Confidence remains visible as high, medium, or low and does not block submission.

## Grading versions

| Version | Read behavior |
| --- | --- |
| `deterministic-v1` | Reconstruct the original deterministic result. Historical attempts are never regraded under a newer policy. |
| `semantic-fill-v2` | Reconstruct v1.1 fill judgments from persisted judgment rows. Calculation and drawing retain their historical manual/advisory representation. |
| `ai-grading-v3` | Persisted fill and rubric judgments compose the official six-type result, including partial credit for calculation and drawing. |

Unknown versions, missing revisions, missing judgments, or malformed evidence are reported as unavailable or malformed. Analytics does not fall back to a current quiz revision or invoke AI to fill gaps.

## Trusted rubric judgments

The browser submits only `requestId`, `attemptId`, and `expectedUpdatedAt`. The server loads the stored answers and exact quiz revision from the database and bundled versioned manifest. It validates provider output against the canonical question rubric, score, criteria IDs, per-criterion maxima, total score, status, confidence, and answer hash before treating it as trusted.

All submission grading uses `gpt-6-luna`, reasoning effort `medium`, and `store: false`. Provider requests do not use personal tutor credits. System calls are recorded in the private rubric-grading usage ledger, not `ai_requests`.

## Persistence and retry

`public.rubric_judgments` contains immutable, finalized evidence, readable by an authenticated user only for that user's submitted attempt. Browser insert, update, and delete are denied. `private.rubric_judge_cache` binds a reservation to owner, attempt, quiz revision, question type, answer hash, judge version, and request identity. Completed responses are reused on retry. A failed provider call leaves the attempt in draft so the student can safely retry.

`finalize_ai_grading_submission` verifies the draft version, request identity, current stored answers and hashes, the exact set of expected judgments, and completed cache evidence. It inserts finalized evidence and writes the submitted result and aggregates in one transaction. Any failed check rolls back the full submission.

## Historical compatibility

Existing v1 and v2 result paths are retained. The v3 UI and rubric evidence render only for `ai-grading-v3`. History reconstructs v3 scores from persisted judgments and never reruns a provider. Mistakes includes v3 incorrect and partial questions using that same persisted evidence. Review remains a deterministic local workflow for the question types it already supports.

Quiz parsing remains able to load historical revisions. A separate publication check requires a scored rubric summing to the question points, reference answer and solution for calculation/drawing, and a valid drawing configuration for current v3 revisions.

## Known limitations before rollout

- The migration applies to a clean local Supabase schema, and `supabase/tests/security.sql` passes locally. No remote migration has been applied.
- `src/types/database.types.ts` was regenerated with the Supabase CLI from the migrated local schema; generated types must not be hand-edited.
- Deno 2.7.10 Edge Function checks pass. Deno 2.9.7 was not locatable from the audited shell, so exact 2.9.7 reproduction remains pending.
- No live provider request, remote migration, Edge Function deployment, production secret change, frontend deployment, or release action is part of this implementation pass.
