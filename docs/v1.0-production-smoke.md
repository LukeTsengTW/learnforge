## 阻擋與尚未執行

正式站點的 headless Chromium console 出現產品字型 CSP 錯誤：`Loading the font '[data-font]' violates ... "font-src 'self'"`。公開部署的 HTML 含 `font-src 'self'`，同一部署的 `math-DypaV1v7.css` 含 KaTeX 的 `data:font/woff2` 來源及 same-origin fallback。瀏覽器因此阻擋了 CSS 的第一個字型來源。這違反本次要求的「沒有 application console error／CSP 阻擋產品必要資源」，即使互動式 Chrome 的已觀察畫面仍可操作，也不能把 smoke 記為全部通過。

額外的 headless 探針在已檢查路由未觀察到 404 asset、mixed content、localhost request 或水平溢出，但因上述 console 失敗而不視為完整 network／responsive 放行。探針早期另有 hash 導覽斷言誤判，已在 ignored `output/` 測試腳本修正；不影響公開站點的互動驗證。發現 CSP 阻擋後依使用者指示停止，沒有修改 workflow、CSP 或產品程式碼。

第一次 smoke 停止時，下列正式站點檢查**尚未執行或尚未完成**：以新帳號重新 login + real Turnstile、wrong／correct／replay recovery 與舊／新密碼登入、六個指定頁面在 360／768／1440 的完整 responsive 矩陣、所有路由的 console／network 完整檢查。當時未建立 `v1.0.0` tag，並要求先修正字型來源與 CSP 的不一致，再重新部署及重跑 smoke。

## CSP／字型 hotfix 與第二次部署

第一次部署 **PASS deploy／FAIL smoke** 的根因已確認：production CSP 原為 `font-src 'self'`，但 Vite 產出的 KaTeX CSS 包含 `data:font/woff2`。Chromium 依 CSP 阻擋該字型來源並記錄 application console error。

本次只將 `vite.config.ts` 的 production directive 改為 `font-src 'self' data:`；其他 CSP directive、KaTeX 設定與 `build.assetsInlineLimit` 均未更動。新增的 production CSP 回歸測試直接檢查 Vite plugin 產生的 policy，確認 data font 可用、沒有 `unsafe-eval`，並保留 Turnstile script／frame、Supabase `connect-src`、`object-src 'none'` 與 `base-uri 'self'`。

Node `24.21.0`／npm `11.19.0` 下，lint、43 個測試檔／354 個測試、`npm run build -- --base=/learnforge/`、quiz check、AI context check、`git diff --check` 及變更檔案敏感內容掃描均 PASS。新 `dist/index.html` 包含 `font-src 'self' data:`，`dist/assets/math-*.css` 仍含 `data:font/woff2`；兩者相容。
