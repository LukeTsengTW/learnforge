## Deterministic baseline reproduction

Inspection of DrawingCanvas, its tests, reducer and CalculationAnswerEditor finished before the first mutation. Production code stayed at v1.6.2 while the initial regressions ran.

**Race 1, confirmed in the supplied event model:** Stylus Priority enabled; A pen down ID=31 → move → up (A committed) → immediately B pen down ID=31 (capture acquired) → delayed A lostpointercapture ID=31 → B move → B up. On v1.6.2 the loss event committed B immediately as a single-point stroke; later move/up could not append. The test catches the premature second emission and requires two complete strokes with the exact three B points. Different IDs pass independently.

The test harness models set/has/release capture ownership. Browser implicit release occurs after up/cancel handlers. A delayed old loss notification does not clear B's new capture; genuine current loss explicitly clears ownership before dispatch. No different-ID substitution hides reuse.

**Race 2, independently confirmed:** Initial controlled strokes=[]; complete A and observe onChange([A]); deliberately keep the parent's original strokes prop while completing B. v1.6.2 emitted [B], not [A,B], even though fireEvent rendered local state. Only explicit rerender acknowledges the result. A separate test showed acknowledgement of A erased visible pending B during replay.

Initial baseline run: DrawingCanvas 39 tests, **8 failed / 31 passed**. Failing cases were reused-ID delayed loss, A–D with no palm/between palm/held palm, rapid dots, flush with deferred acknowledgement, A+B accumulation and pending repaint. Normal different-ID drawing, genuine loss recovery and external replacement passed. After an additional deferred-history test, the final DrawingCanvas count is 40.

## Narrow fix

- Pointerup appends the final point and commits. Pointercancel commits existing partial points without appending cancellation coordinates. Both rely on browser implicit capture release.
- Lost capture is a recovery handler: it only terminates the matching pending stroke when hasPointerCapture is false. A new capture for the reused ID makes an old notification a no-op.
- Imperative flush commits/clears pending before explicit release, preventing reentrant or later capture-loss duplicate commits; an idle flush returns the latest locally committed strokes.
- A synchronous committed-strokes ref drives reducer additions and canvas replay before parent acknowledgement. Local visible state supports tools/export while waiting. A changed controlled strokes identity reconciles authoritatively, including replacement/clear. Parent acknowledgement replays committed plus active pending ink. No stroke schema changes, timers, throttling or delayed pointerdown.
- Undo/redo/clear repaint the emitted local state immediately; PNG uses the visible committed history. Existing parent-controlled integration and answer-mode flush contract remain intact.

The capture assumptions were checked against [W3C Pointer Events: Element capture APIs](https://www.w3.org/TR/pointerevents3/#extensions-to-the-element-interface) and [implicit release](https://www.w3.org/TR/pointerevents3/#implicit-release-of-pointer-capture): hasPointerCapture reflects pending capture immediately after setPointerCapture; the UA releases after up/cancel.
