## 2. Restore architecture

Quiz 草稿及 Result 每次載入只呼叫 `ai-responses` 讀 DB，不自動呼叫 GPT，也不保留 credit。從 History 重新打開 submitted attempt 走相同流程。回覆只存在當前 React state 作顯示；DB `ai_requests` 是權威來源，未新增 AI localStorage 鏡像。有效 reservation 只作「仍在處理」提示，可手動重新檢查；refunded／expired 不顯示回覆。

## 3. AI response identity

以 verified `user_id`、`attempt_id`、`question_id`、`feature` 隔離。僅 `status='completed'` 的回覆可恢復；同一 identity 按 `completed_at DESC, created_at DESC, id DESC` 選最新。Hint 可有多筆，本版預設只顯示最新一筆；Explain Mistake／Explain Solution 同理。

## 4. Read API

`GET ai-responses?attemptId=<uuid>` 回 `{responses:[{questionId,feature,response,completedAt}],pending:[{questionId,feature}]}`。Endpoint 使用 `withSupabase({ auth: 'user' })`，先用 user-scoped RLS client 確認 attempt ownership，再用 service-only RPC 讀私有 ledger；不接受 userId。不存在及非本人 attempt 都回同一 generic 404。回應 `no-store`，不投影 token、provider ID、模型欄位、error_code 或原始 ledger metadata。

## 5. Regenerate behavior

有回覆時顯示「重新產生 AI 提示／解釋」及 1／2 credits；學生明確點擊才建立新 requestId。額度不足時隱藏操作，但既有回覆繼續可讀。最新完成回覆再次開頁會取代舊回覆。免費題庫 Hint 原本功能保留。

## 6. Idempotent retry behavior

Client 狀態集中為 `idle`、`loading`、`completed`、`retryable`、`pending`、`quota_exhausted`。網路結果不明時保留原 requestId，首次「重試取得前次說明」仍用同 ID；server 的 completed replay 回既有 response、reserved 回處理中、已關閉 request 回固定結果。只有明確「重新產生」才使用新 UUID。頁面重開後若看見 reserved，提供手動「重新檢查」，沒有無限輪詢。

## 7. Quota UX

`get_ai_quota_status` 同時回 DB `serverNow` 與 `nextCreditAt`。Client 僅在 remaining=0 時用兩者差值顯示最早恢復 **1 credit** 的相對時間；不把 rolling window 當作整批重置。正確額度仍完全由 DB／Edge 決定，client clock 不參與計費。

## 8. Usage history

受保護的 `#/ai-usage` 顯示本人 remaining／used／20、5 小時功能完成次數及每頁 20 筆紀錄。`ai-usage` 用 `(created_at DESC, id DESC)` 游標分頁，對外只回時間、quiz／question identity、功能、credits、友善 status；原始 UUID 僅在 opaque next cursor。題庫標題／Q 序號從 bundled quiz revision 解析；找不到歷史 revision 時退回 quiz id／question id。手機使用語義化有序列表，狀態有文字。

## 9. Token observability

Service-only `get_ai_usage_summary` 回 `last5Hours`、`last24Hours`、`allTime`：request、completed、refunded、expired 次數、三功能完成次數，以及 input／cached input／output／reasoning token 總和。Provider usage 欄位 `NULL` 表示未回報，合計時視為 0，另以 `usageReportedCount` 指出有回報欄位的 request 數。學生 UI 不顯示 token 或美元估算，沒有硬編價格。

## 10. Database changes

未新增 table，也未修改 v0.4 migration。第一個 v0.5 migration 新增三個查詢索引、三個 private projection RPC，並在 quota status 增加 `serverNow`。第二個 migration 修正 usage page 的權限邊界：service-only RPC 只取 `attempt_id`，由 Edge 的 RLS client 解析 quiz metadata。兩次都在 migration list／dry-run 確認只有預期項目後 push。Linked schema 變更後已重新生成 TypeScript types。

## 11. Indexes and query plans

- 最新完成回覆：partial `(user_id,attempt_id,question_id,feature,completed_at DESC,created_at DESC,id DESC) WHERE status='completed'`。
- 進行中訊號：同 identity／created order 的 reserved partial index。
- 用量分頁及個人時間窗：`(user_id,created_at DESC,id DESC)`。

對 linked 安全 fixture 執行 `EXPLAIN`。當時正式 ledger 只有 3 筆，planner 依成本選 seq scan；在同一 read-only transaction 以 `SET LOCAL enable_seqscan=off` 驗證最新 completed lookup 使用 `ai_requests_restore_completed_idx`、游標分頁使用 `ai_requests_user_cursor_idx` 的 Index Only Scan。5 小時聚合在極小 ledger 上選既有 `(user_id,request_id)` unique index 加時間 filter；沒有宣稱大資料量性能已由這個 fixture 證明，也未對 production 執行 `EXPLAIN ANALYZE` 或額外 ANALYZE。

## 12. RLS and RPC

`ai_requests` 繼續對 browser 的 anon／authenticated 無 table SELECT。三個新 RPC 固定空 `search_path`、`security invoker`，撤銷 PUBLIC／anon／authenticated EXECUTE，只授 service_role。所有 userId 由 Edge verified JWT claim 填入，browser 不能直接帶 arbitrary userId 呼叫 RPC。Attempt metadata 查詢仍走 user-scoped RLS client。

## 13. Edge Functions

新增 `ai-responses` v1、`ai-usage` v1，更新 `ai-quota` v2；hosted list 均為 ACTIVE、`verify_jwt=false`。Handler 使用 `withSupabase({ auth: 'user' })`。`ai-tutor` v1 未修改／未重部署，`password-hint` 未修改。四個 AI entrypoint 已通過 Deno type check；config regression test 檢查 JWT 設定。

## 26. Known limitations

- Usage page 只顯示每個 request 的基本資訊，未提供管理員分析、圖表或美元成本。
- Reserved request 在重開頁後只可手動重新檢查；沒有無限輪詢或跨重新整理保存未知 requestId。
- 未建立 completed response 的清理；refunded／expired 清理只是文件政策，沒有 Cron。
- Query plan 是少量資料 fixture 的驗證，尚需 ledger 成長後再觀察實際 planner／負載。Responsive 是 Chrome viewport，未覆蓋實體裝置。
