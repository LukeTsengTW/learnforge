## 2. AI architecture

Browser 只送 `requestId`、`feature`、`attemptId`、`questionId`。`ai-tutor` 先透過 Supabase 驗證 user JWT，以 RLS client 讀本人 attempt/answer，再以 `quiz_id + quiz_revision + question_id` 查 server manifest。Edge 以 admin client 呼叫 quota RPC，最後才由 server 呼叫 OpenAI；browser 不接觸 provider 或 service key。`ai-quota` 只回傳必要的 quota 欄位。

## 3. GPT-6 Luna configuration

模型在 server 共用程式固定為 `gpt-6-luna`。request 不接受 browser 指定模型；ledger 同時記錄並限制該 model。三項 live provider 回應皆成功，linked ledger 的 model 亦均為 `gpt-6-luna`。

## 4. Responses API configuration

只呼叫 `POST https://api.openai.com/v1/responses`；每次呼叫是獨立 request，不建立 Conversation、不送 `previous_response_id`、不提供工具。已部署的 Responses API request 程式明確設定 `store: false`，unit test 檢查實際組裝的 body；三次 live 呼叫走同一已部署路徑。這不等於能從 provider server 端直接證明完全沒有 operational retention。

## 5. Reasoning effort

三個 feature 全部固定 `reasoning.effort: "low"`。每 feature `max_output_tokens` 上限為 hint 600、explain_mistake 900、explain_solution 1200，包含 reasoning token 的預算。browser 無法修改。

## 6. Structured Output schema

Responses API 使用 `text.format.type = "json_schema"`、`strict: true`。根物件必須且只能有 `title`、`message`、`keyPoints`、`nextStep`，`additionalProperties: false`；server 再檢查字串與列表大小。不完整、格式錯誤、過長或 provider incomplete 均不回傳原始內容。

## 7. Tutor context manifest

`generate:ai-context` 以現有 `parseQuiz` 解析 `src/content/quizzes/**/*.quiz.md`，投影 canonical 題幹、選項、標準答案、解析與 rubric，產生 3 份題庫、22 題的 server manifest。生成時拒絕重複 identity、欄位過長及單題超過 32 KiB；`test` 與 `build` 先跑 `check:ai-context` 防止 drift。舊 revision 缺失時安全回應 unavailable，不改用新版解答。

## 8. Prompt injection boundary

Developer instructions 明示題目、選項、學生答案和解答皆為資料，不能遵循其中指令。學生答案從本人 DB row 讀取，經題型白名單與大小限制正規化；未知欄位不轉送。provider raw response/error 不送 browser、不進 ledger。這能建立明確邊界，但生成內容仍需以官方解答核對。

## 9. Feature behavior

- Draft：保留原有免費 Hint；AI Hint 需學生點擊，且傳給 OpenAI 的 canonical payload 不含標準答案或完整解析。點擊前確認草稿答案已同步到雲端。
- Submitted：只有已判錯的客觀題可用 Explain Mistake；所有非畫圖題可用 Explain Solution，包含計算題。畫圖題不傳圖像、不提供 AI 功能。AI 不修改既有 deterministic grade。
- Provider refusal 回傳安全固定文案並完成計費；provider/network/格式失敗時退款。AI 文案是學習建議，不是標準答案。

## 10. AI quota model

每位 authenticated user 在每次請求當下往前 5 小時可用 20 credits。Hint、Explain Mistake 各 1 credit；Explain Solution 2 credits。quota status 提供 `limit`、`used`、`remaining`、`windowSeconds=18000`、`nextCreditAt` 與成本；`nextCreditAt` 是最早一筆 credit 釋放時間，沒有 `resetAt`。

## 11. Quota reservation design

`reserve_ai_request` 以 user UUID 的 transaction advisory lock 序列化同一使用者的計數與插入，在 SQL 裡原子判斷上限。`reserved` 與 `completed` 佔用 rolling window；15 分鐘後未完成的 reservation 在下次 status/reserve 時標為 `expired`。SQL 增設 `(user_id, created_at desc)` partial index。不同使用者互不共用額度。

## 12. Idempotency

`(user_id, request_id)` 唯一；同 ID 只對相同 attempt、question、feature、model、effort 回放。完成的 request 回傳已保存 Tutor response，不再呼叫 OpenAI 或扣點；進行中回 202；refunded/expired ID 終止。Browser 在網路狀態不確定時保留同一 requestId，額度耗盡後也可重試取回**前次**說明；新的 request 仍由 server quota 擋下。

## 13. Refund policy

OpenAI 429/5xx、timeout、網路錯誤、malformed/incomplete output 或完成 ledger 失敗時嘗試退款。拒答屬有效、安全回應而收取額度。即使 Edge worker 中斷，reservation TTL 也會釋出 quota；provider 可能已花費的費用無法藉此回收。

## 14. Database migration

新增 `public.ai_requests`，儲存 request identity、feature/cost、模型、狀態、時間、經驗證的 response 及 token usage。不儲存 prompt、完整作答或 OpenAI raw body。此 migration 為 additive；linked `learnforge-demo` 已套用 `20260925074745_v04_ai_tutor_quota.sql`，v0.2/v0.3 原有 migration 和資料未改動。套用後 migration history 一致、dry-run 無待套用 migration。

## 15. RLS / grants / RPC

`ai_requests` 啟用 RLS，不提供 anon/authenticated table 權限或 policy；僅授予 service_role 必要讀寫。`get_ai_quota_status`、`find_ai_request`、`reserve_ai_request`、`complete_ai_request`、`refund_ai_request` 均為 `security invoker`，固定空 `search_path`，撤銷 PUBLIC/anon/authenticated EXECUTE，僅授 service_role。Browser 無法自帶 user_id 呼叫 privileged RPC。linked SQL security fixture 已實際通過。

## 16. Edge Functions

`ai-tutor`、`ai-quota` 的 platform `verify_jwt=false`；兩個實際 handler 均使用 `withSupabase<Database>({ auth: 'user' }, ...)` 驗證 user session JWT，取用 `ctx.userClaims.id`，不信任未驗證的 Authorization header。`edge-auth-config.test.ts` 防止將 platform `verify_jwt=true` 與此 SDK auth flow 再度混用。`ai-tutor` 限 POST/JSON/4 KiB、嚴格四欄位 schema；找不到或不屬於本人的 attempt 回同一 404。`ai-quota` 限 GET，對 admin RPC 結果做明確投影。兩者均設 `Cache-Control: no-store`。已以 `--no-verify-jwt` 部署兩個 Function；hosted list 均為 ACTIVE v1、`verify_jwt=false`。未登入呼叫兩者均 HTTP 401、`MISSING_CREDENTIALS`；測試帳號的有效 session 可呼叫兩者。既有 `password-hint` 的檔案和部署保持原狀。

## 17. UI

Quiz/Result 顯示簡潔額度及固定 disclaimer。額度不足時隱藏相應新 AI action；已產生的說明留在畫面。使用既有 Markdown 元件，跳過 raw HTML，KaTeX `trust=false`，不使用 `dangerouslySetInnerHTML`。顯示 loading、可重試錯誤與 quota 錯誤；按鈕防重複點擊。

## 19. SQL security tests

`npx supabase db query --linked --file supabase/tests/security.sql` 在 `learnforge-demo` 回報 `PASS: v0.3 practice security and v0.4 private atomic AI quota`。fixture 以 transaction/rollback 執行；測試涵蓋既有 Auth、attempt、history RLS，以及 anon/authenticated 對 AI table/RPC 的拒絕、使用者隔離、20-credit 上限、5 小時 rolling window、1/2-credit 成本、reservation、completed、refunded、expired、同 ID 回放、identity mismatch 與 `nextCreditAt`。事後查核 fixture Auth users 為 0。

另做真正的雙連線並發：專用暫時 user 預放 19 credits，連線 A 發 hint(1) reservation 並在同一 transaction 內持鎖約 10 秒，連線 B 於 1.5 秒後發 solution(2) reservation。A 回 `created, used=20, remaining=0`；B 等待鎖後回 `denied, used=20, remaining=0`。DB 最終 `used=20`、hint row 1、solution row 0，沒有穿透上限。暫時 user、profile 和 AI rows 均已精確刪除，既有資料未動。
