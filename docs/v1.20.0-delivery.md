## Scope

Calculation handwriting now stores an ordered set of pages. Each page has an independent canvas history and retains its own state while the learner navigates between pages. The editor supports add, select, delete confirmation, expanded view, page-local input controls, recovery, and PNG export. The implementation adds draft schema 3 while preserving schema-1/2 draft promotion and legacy submitted-attempt readers.

The server path is versioned as V5 across draft validation/save, submission idempotency and claim state, ordered raster images, AI grading, rubric finalization, submitted history, and analytics. The two new migrations are additive. They do not rewrite or drop existing quiz, draft, attempt, auth, or rubric data. No quiz-bank content was changed and no dependency was added.

## Rollback plan

Before any production mutation, stop and preserve the previous v1.19.0 release as the last known-good runtime. Apply only the reviewed additive migrations and deploy only named functions. If a migration or deployment fails before schema-3 writes are enabled, stop rollout and restore Pages to the previous verified deployment; do not delete migration history or database objects. Once any schema-3 draft or attempt may have been written, preserve it and use a forward fix or a schema-3-aware recovery release. Do not roll application code back to v1.19.0 while schema-3 data exists, because that version cannot read the new answer contract. Do not use destructive rollback SQL.
