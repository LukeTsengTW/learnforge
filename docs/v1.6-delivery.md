## Product delta and theme semantics

- First-class Light and Dark themes use centralized semantic CSS tokens and a root `data-theme="light|dark"` attribute. Global and authoring styles share the palette. Page surfaces, header/navigation, cards/library, text, controls, inputs/filters, borders, status states, code and KaTeX switch consistently. Existing Light values are preserved.
- The native header **深色模式** button has a stable visible accessible name, `aria-pressed`, Enter/Space support and a visible focus outline. Header wrapping preserves mobile navigation.
- Explicit choices are persisted under `learnforge:theme` and restored on reload. Without a valid stored choice, startup uses `prefers-color-scheme` and does not persist that implicit default. OS changes do not override explicit choices. Blocked storage still permits switching during the visit.
- A synchronous same-origin classic head script at `/learnforge/assets/theme-init.js` applies the root theme before React and application CSS load, avoiding an obvious saved-dark Light flash without changing CSP. Its bytes are unchanged from the original bootstrap. No theme or parser dependency was added.
- Drawing paper and stroke colors remain fixed to preserve saved/exported drawings. The surrounding controls and surfaces use theme tokens.

2. The first continuation moved the bootstrap and updated the reference but introduced an unnecessary jsdom test environment. Node's `readFileSync(new URL(..., import.meta.url))` then failed with **TypeError: The URL must be of scheme file**. This was an agent-introduced test-harness defect, not a theme product defect; no commit or push was made.
3. The authorized correction removed jsdom/DOMParser and used Node source-text assertions. **Three focused files / 109 tests passed**. The real `/learnforge/` build then proved exact assets placement, byte identity, synchronous pre-paint ordering, old-root absence and no generated-asset collision.
4. The following HTTP loopback canonical smoke failed with **Application asset URL is invalid**. Its prior stop report incorrectly called stack line 192 a static-import enqueue. Line 192 actually processes HTML `linkedAssets`; genuine static imports are processed at line 200. Diagnosis recorded the following exact rejected reference, without modifying canonical source:

```json
"//local.adguard.org?ts=1791347690761&amp;type=content-script&amp;dmn=127.0.0.1:50067&amp;url=http%3A%2F%2F127.0.0.1%3A50067%2Flearnforge%2F&amp;app=node.exe&amp;css=2&amp;js=1&amp;rel=1&amp;rji=1&amp;sbe=1&amp;stealth=0"
```

Parent URL: `http://127.0.0.1:50067/learnforge/`. Received source: **index.html**, reference offset **901**, script-tag offset **829** (zero-based UTF-16). A short escaped lexical window is:

```json
"\" src=\"//local.adguard.org?ts=1791347690761&amp;type=content-script&amp;dmn=127.0.0.1:50067&amp;url=http%3A%2F%2F127.0.0.1"
```

`assetUrl()` line 36 correctly rejects **%**, **?** and **&** before URL construction/fetch. Received HTML SHA-256 was `c6b0ed843a8eaca1e5853dbcb1263e4b4de4e83392bfcfc09bdd202613249294`; disk HTML was `765f12c2e10f9acc4d19db20ec9decfc2912a149e8eedf47abbbfd751b12c7b7` and did not contain the reference. This proves **Case C: AdGuard HTTP loopback response injection**, not a static ESM specifier, Vite output defect or lexer false positive. `Cache-Control: no-transform` did not prevent the injection in a read-only diagnostic experiment.

The ignored offline helper now supplies exact dist file bytes through the canonical tool's existing `fetchImpl` hook and `allowLocal: true`; it performs no network or system-security mutation.
