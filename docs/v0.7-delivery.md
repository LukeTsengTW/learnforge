## 2. Multimodal architecture

Browser 僅送四個識別欄位；`ai-drawing` 以 JWT 確認使用者，讀取本人已提交 attempt、當時版本的題目及已保存答案，檢查 rubric 後在 Edge 記憶體中重建 PNG。私有 quota RPC 保留 4 credits，OpenAI Responses API 回傳結構化分析，server 驗證後寫入私有 `ai_requests`。Result 顯示 AI 建議，正式成績仍走既有 deterministic grading。

## 3. Authoritative stroke source

唯一繪圖來源是 `public.answers` 中與本人 submitted attempt／`question_id` 相符的 `answer` JSON。題目、參考答案、rubric 和畫布尺寸取自 `(quiz_id, quiz_revision, question_id)` 對應的生成 manifest。Endpoint 精確接受 `{requestId, feature, attemptId, questionId}`；`image`、URL、base64、PNG、strokes、prompt、rubric、模型及點數等額外欄位一律拒絕。

## 4. Server rasterization

純 TypeScript rasterizer 依原始 logical canvas 座標繪製 round cap／join 線段；2×2 子像素 coverage 保留邊緣。畫筆使用 source-over，橡皮擦使用 destination-out；按筆畫順序合成後鋪白底。每筆只合成實際觸及的像素，避免大量短筆畫反覆掃描整張畫布。只允許既有 drawing 色票和合法寬度／座標。限制為 1200×1200、256 筆、6000 點及 2500 萬幾何像素工作量。

## 5. PNG generation

輸出為 opaque RGBA PNG，使用 Web `CompressionStream('deflate')`、PNG chunk 與 CRC32，不依賴 native canvas 或外部 raster service。PNG 超過 2 MB 時在扣點前拒絕；圖像只在這次 Edge request 的記憶體中用於 vision input，ledger 不保存 PNG 或 data URL。

## 6. Blank detection

白底合成後以可見像素判斷，須達 `max(12, ceil(width × height × 0.00002))` 個任一 RGB channel 小於 245 的像素。空白、極小誤觸與全擦除在扣點前拒絕；這只是可用性門檻，並非電路正確性判斷。

## 7. OpenAI vision config

固定 `gpt-6-luna`、Responses API `input_image` PNG data URL、嚴格 Structured Outputs、`store:false`，不提供 tools。以 [GPT-6 Luna 官方模型頁](https://developers.openai.com/api/docs/models/gpt-6-luna)、[vision input 文件](https://developers.openai.com/api/docs/guides/images-vision) 和 [Structured Outputs 文件](https://developers.openai.com/api/docs/guides/structured-outputs) 核對；linked 專案兩次真實 vision 回覆亦成功。模型專屬影像 sizing 表未列 Luna，故不宣稱精確 image token 算法。

## 8. Image detail

每次 `input_image` 明確設定 `detail:'high'`。實際產生的單題 PNG 由 server 送出；沒有接受 browser 上傳的圖像。

## 9. Reasoning effort

圖像分析固定 `reasoning.effort:'medium'`；DB constraint 和 reservation RPC 也只接受此 feature 使用 medium。既有 Tutor 的 low 與計算題 medium 規則仍保留。

## 10. Structured Output

Provider 必須回傳嚴格 JSON schema，所有 object 均關閉額外欄位。內容包含總分、逐項 criterion 分數／狀態／回饋、可見元素、缺少或不清楚處、總結、confidence 及人工覆核旗標；refusal 走獨立無分數回應。Parser 拒絕未完成、格式異常或超過保存大小限制的結果，失敗會退還 reservation。

## 11. Rubric validation

只有 drawing 題、有效畫布、參考答案、解法及完整可量化 scored rubric 才可呼叫。各 criterion 必須有描述與正分，ID 依 manifest 的 `r1…rN`，總分須等於題目 points。Browser 無權指定或修改 rubric。

## 12. Score validation

Server 驗證 criterion 數量／ID／唯一性、各項 `maxScore`、`awardedScore` 範圍、full／partial／none 狀態一致性，以及總分等於逐項之和且不超過題目分數。拒絕 NaN、Infinity、負分、超額、缺項、重複項與額外欄位。已保存回覆在恢復前再次驗證。

## 13. Visual prompt injection boundary

Developer instructions 將手寫文字及學生圖像明確視為不可信資料，禁止服從圖中的角色、rubric、分數或輸出格式指令。測試檢查此指令邊界；它降低提示注入風險，但不能保證模型對所有惡意影像都免疫。

## 14. Quota

`drawing_analysis` 每次 4 credits，與既有每 5 小時 20 credits 共用私有 ledger。RPC 在 per-user transaction advisory lock 下計算已完成與有效保留，處理同時請求和同 ID 回放；失敗可退還。SQL rollback fixture 覆蓋 4 點可用、只剩 3 點拒絕、同 ID 不重扣及退款恢復。

## 15. Persistence / restore

完成結果只保存於 `ai_requests.response`。`ai-responses` 確認本人 submitted attempt 與該版本 scored drawing 後，恢復最新完成分析；有效保留只投影為 pending。History 重開與整頁 reload 都只讀取，不重新扣點。明確「重新分析」才產生新 request ID；不確定的網路失敗以同 ID 重試。

## 32. Limitations

AI 依可見圖形提供建議，可能誤辨字形、線段、連接或手寫公式；不執行電路模擬、形式化 topology 驗證或電氣安全認證。沒有圖像準確率 benchmark；兩次 live 回應只能證明整合。Rasterizer 的 2×2 抗鋸齒近似 browser canvas，無 pixel-perfect 一致保證。影像大小／幾何複雜度上限會拒絕部分圖；學生需自行參照解析與教師判斷。

## 33. Recommended v0.8

優先補帳號復原與同步可靠性：可驗證的復原方式、註冊防濫用、recovery UI、多裝置衝突測試與備份政策。圖像品質評估可另建多種正確／缺項／模糊圖的人工標註資料集，再評估模型建議與 rubric 的一致性。
