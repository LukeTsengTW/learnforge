## Request and decision

Human 要求：移除「數位邏輯與基礎數學」、「布林代數基礎」、「離散數學：關係」三份題庫，其餘題庫保持不變；修改交由 reviewer 審查，並以 Playwright 測試；之後下達 release。

對應的 quiz id：`demo`（兩個 revision：`v1-7d7c900e`［封存］、`v2-handwriting`［current］）、`boolean-algebra`（revision 1）、`relations`（revision 1）。

## Design

- **發布的題庫**：三個題庫的 Markdown 從 `src/content/quizzes/` 移出，bundled catalog 因此只剩 4 份 current quizzes：`discrete-math`（revision 2 current、revision 1 封存）、`discrete-math-ch1-counting-examples/1`、`discrete-math-exercises-2026/1`、`discrete-math-ch3-set-theory-examples/1`。全庫為 5 revisions／4 current／74 questions／74 canonical contexts（`check:quizzes`、`check:ai-context` 的輸出）。
- **Edge 的 canonical context**：`supabase/functions/_shared/quiz-context.generated.ts` 以 `npm run generate:ai-context` 重新產生，由 103 個 context 降為 74 個；保留的 74 個與 v1.14.1 的內容逐位元相同，移除的 29 個是 `boolean-algebra/1`（7）、`demo/v1-7d7c900e`（7）、`demo/v2-handwriting`（7）、`relations/1`（8）。
- **測試 fixture**：46 個測試檔把這三個題庫當成豐富的測試資料（計算題、手寫、多種題型）。三個題庫的 Markdown 以 `git mv` 移到 `src/test-fixtures/quizzes/`（內容與 v1.14.1 的 blob 相同），測試以 `src/test-fixtures/fixture-quizzes.test-helper.ts` 的 `withFixtureQuizzes`／`withFixtureContexts` 以 `vi.mock` 選擇加入；產品的 bundle 與 generated context 都不含這些檔案。這些 fixture 不會進入 production。
- **Home**：寫死的精選題庫原為 `boolean-algebra`，改為 `discrete-math-ch1-counting-examples`（「離散數學第一章：計數的基本原理－例題練習」）。期中考的描述含未渲染的 LaTeX 原始碼，卡片會原樣顯示，所以沒有選它。`index.html` 的 meta description 把「數位邏輯與基礎數學」改為「離散數學」。
- `quiz-loader.ts`：移除只有測試使用的 `demoQuiz` 匯出。

## What does not change

留下的四份題庫的內容與 74 個 canonical context、parser、評分、migration、RLS、Auth／secrets／provider configuration、dependency。Edge function 的原始碼除了 generated canonical context（`_shared/quiz-context.generated.ts`，六個 function 都經由 `_shared/ai-tutor.ts` 打包它）以外不變。既有使用者在資料庫中的紀錄不動。

## User-visible consequences

- Library、Home 與直接開啟 `#/quiz/demo`（找不到這個練習）：三份題庫不再存在。
- 這三份題庫過去的作答仍在資料庫中。練習紀錄對它們顯示「題目版本無法載入」與原始 quiz id，因為題目檔已不在 bundle；練習紀錄只對 deterministic-v1 的紀錄顯示已保存的分數，其他 grading version 顯示「— / —」；結果頁無法顯示這些紀錄的分數、答案與解析（既有的降級行為，自題庫與練習紀錄引入時起就是這樣設計）。學習分析與錯題複習提示有幾筆舊版紀錄因題目版本不存在而未納入。「無法安全重現正式分數，請稍後重試」這句文案對它們有誤導（永遠不會恢復）；本版沒有改文案。資料庫中這三份題庫的未完成草稿沒有 UI 可以捨棄。
- 已發布的題庫只剩單選（12 題）與計算題（62 題）；多選、是非、填空、畫圖題在 production 沒有題目，但 Library 的題型篩選仍列出這四種（選取後顯示「找不到符合條件的題庫。」）。
- Home 的邏輯閘插圖、說明文字「從一個邏輯閘，開始理解。」與卡片的「x² − 5x + 6」裝飾與已移除的題庫內容有關，這版沒有改（human 沒有要求）。

## Review

Review 由 sub-agent（code reviewer）執行，三輪。

- Cycle 1：REWORK。有測試經由 mock 不再驗證真正發布的內容（false-green 風險）、過期的註解等 blocking／should-fix；全部已修正。
- Cycle 2：PASS。
- Cycle 3（包含 Home 精選題庫變更與 v4-capability 加強後）：PASS，沒有 blocking。Reviewer 在 cycle 3 的 tree（release prep 之前，尚未升版與寫文件）重跑 test、lint、tsc、`git diff --check`。

- Release-prep review（commit 前的 working tree）：cycle 1 REWORK，五處文件錯誤（blocking）與四個 nit：文件說 Edge function 原始碼不變，但 generated context 就是 Edge 原始碼；Edge／Pages 空窗只有 v4 草稿與提交、AI 會被拒絕，v3 草稿仍可儲存；分數的說法不一致且部分不實；設計來源的年代錯誤；`release-final-gate.mjs` 的描述錯誤。已全部修正，文件雜湊改變，cycle 2 的結果由 post-commit report 記錄。

## Risk, classifier and acceptance plan

`release:classify --base v1.14.1 --head HEAD --include-working-tree`：**security-ai／Risk C／providerCanaryRequired=false**。Risk C 的原因有兩個：路徑被判為 unrecognized（`.env.local`、package files、`index.html`、`src/App-v4.test.tsx`、`src/test-fixtures/**`）、`quiz-context.generated.ts` 為 Database or Edge behavior。沒有 provider、grading、prompt 路徑的實質變更（AI 與 grading 的路徑只有測試檔，classifier 標示為不需要 provider canary），所以不需要付費的 provider canary。

- Release tools（commit 前，含全部變更的 working tree，64 個路徑）：`release:check --base v1.14.1` 10／10 PASS（report：version 1.15.0、security-ai／Risk C／providerCanaryRequired=false、111 files／1,683 tests）；`release:preflight --base v1.14.1 --version 1.15.0 --branch master --require-tag-absent`（沒有 `--sha` 與 `--require-clean`）PASS。此時 HEAD 仍是基準，所以 manifest 的 gitSha 與 baseSha 都是 `6e98fc7c…`；commit 後以嚴格形式重跑，結果由 post-commit report 記錄。
- **需要 Edge 部署**：generated context 改變，依 release prep 的規則重新部署六個使用它的 Edge function：`ai-tutor`、`ai-grade`、`ai-drawing`、`ai-responses`、`save-quiz-draft`、`submit-quiz`。順序：candidate CI → Edge → exact-SHA Pages → production smoke。
- **Edge 與 Pages 之間的空窗**：Edge 先部署後，production 的舊 Pages 仍會列出三份被移除的題庫。這段期間：三份題庫的提交（`submit-quiz`）與 AI 請求會被拒絕，因為 Edge 已找不到它們的 context；`demo/v2-handwriting` 的 v4 草稿因為經由 `save-quiz-draft`（也依 context 驗證）而無法儲存；`boolean-algebra`、`relations` 與 `demo/v1-7d7c900e` 的 v3 草稿經由 `save_quiz_attempt_v3` RPC 儲存，不受 context 影響，仍可儲存。這段時間要縮短（runtime health 通過後立刻部署 Pages）。反過來先部署 Pages 則舊 Edge 仍接受被移除題庫的請求，沒有使用者可見的問題，但 context 未清理；因此依既有順序先 Edge。
- 部署後驗收：release.json identity、canonical public smoke、Library 只有 4 份題庫且搜尋不到被移除的名稱、`#/quiz/demo` 的行為、資產爬取、未登入的瀏覽器 smoke、六個 Edge function 的 runtime health（零憑證、不帶 body）。登入後的 canary 是否需要，由 release review 決定。

## Not changed in this release (known leftovers)

- `scripts/release-browser-e2e.mjs`、`scripts/release-real-turnstile-e2e.mjs`、`scripts/release-final-gate.mjs` 與 `docs/release-checklist.md` 較舊段落仍以 `/quiz/demo` 為目標。`release-browser-e2e.mjs` 與 `release-real-turnstile-e2e.mjs` 是需要後端與專用註冊帳號的選用 script（`release-browser-e2e` 使用已連結的開發後端），它們的 `/quiz/demo` 步驟會失敗，使用前必須改用保留的題庫；`release-final-gate.mjs` 是只允許 127.0.0.1／localhost 的唯讀 smoke，不使用憑證或帳號，它的 `/quiz/demo` 步驟只檢查未登入會轉到登入頁，仍會通過（`RequireAuth` 包住題庫路由），只是不再對應一份存在的題庫。三者都不在 `release:check` 或 CI 中，本版沒有改它們；`release-browser-e2e` 與 `release-real-turnstile-e2e` 的改動需要真實後端才能驗證。
- README 的 DSL specification 範例區塊（`@quiz id="demo" …`）是語法範例，不是題庫清單，沒有改。
- 歷史 delivery 文件與較早的 CHANGELOG／README snapshot 保留原狀。
